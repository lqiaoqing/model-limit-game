# Challenge: model-limit-v2

> 目标：同一规格，评估 Coding Agent 能否驾驭复杂、互相耦合、可自动验证的 3D 游戏系统。

## 公共规格（所有模型相同）

基于 **Neon Siege Arena**（Three.js + TypeScript + Vite）完成下列能力。允许在任意仓库从零实现，或从 V1 升级。

### A. 战斗深度

1. **三套可切换武器**（默认键 1/2/3 或等价 UI）  
   - Plasma / Rail（穿透）/ Scatter（多弹丸）  
   - 切换后数值身份不得漂移（往返切换回默认武器，射速/伤害应恢复）。
2. **规则修改型升级**（≥6 个，不只是 +stat）  
   - 至少覆盖：击杀连锁、过热特殊处理、穿透相关、冲刺相关、护盾破裂相关中的 ≥3 类。  
   - 升级三选一仍可用。
3. **Synergy 可观察**  
   - 例如：连锁 + 暴击、穿透 + 击杀回热、过热 EMP 等至少 2 条。

### B. 遭遇编排

4. **威胁预算 / 小队编成**（非 Stress 波次）  
   - 不止固定 chaser/ranged 比例；存在可配置配方（≥3 种）。
5. **出生预警**  
   - 新单位入场有可读 telegraph。

### C. Boss

6. **多阶段 Boss**（≥2 阶段，HP 阈值切换）  
   - 阶段切换有视觉/反馈；阶段行为不同（弹型/召唤/移速等）。

### D. 技术与工程

7. **Stress / 性能路径**  
   - 可开关的高密度敌潮；敌人实例化渲染；粒子有池化或实例化。
8. **架构边界**  
   - 战斗解析、遥测/诊断、渲染后端（或等价）有独立模块，避免单文件上帝对象失控。
9. **自动化验证**  
   - 可构建（`tsc`/`vite build`）；至少 1 个 bot/集成测试；诊断钩子供脚本读取。

### E. 基准（加分项）

10. **多 Seed 平衡遥测**  
    - 可重复跑多 seed，输出 kills/DPS/FPS 等与 scorecard。
11. **双渲染后端骨架或文档化取舍**  
    - WebGPU 可选 / 明确 WebGL-only 理由。

## 交付物

- 可运行源码（Node 20+）
- `README`：启动、键位、脚本
- 测试可执行：`npm test` 或等价命令
- （可选）`artifacts/balance/` 或自定义 scorecard

## 评分

见 `scoring.json`。评估命令：

```bash
npm run arena:eval -- --model <id> --root <impl-root> --challenge model-limit-v2
```
